# PRD — 包公 BaoGong

## 1. 問題陳述

內地企業家想在香港開有限公司 + 銀行戶口，面對：
- **價格不透明**：低價引流（HKD 1,000 註冊），後續隱藏收費（年審、報稅、地址、開戶陪同）暴增。
- **服務質素參差**：秘書公司是否持 TCSP 牌、有無實際辦公室、有無開戶經驗，客戶無從判斷。
- **資訊不對稱**：不懂 NNC1、NAR1、商業登記、公司秘書法定責任，容易被誤導。
- **無可信評價**：現有評價多為廣告或假評。

## 2. 用戶角色

| 角色 | 描述 | 主要動作 |
|---|---|---|
| **訪客** | 未註冊，來自小紅書／知乎／SEO | 搜尋、瀏覽名單、看比較、讀教育文章 |
| **買家會員** | 內地客戶，已註冊 | 發 RFQ、收報價、留評價、上傳 NNC1 核驗 |
| **秘書公司（未認領）** | 官方名單自動帶出 | — （頁面存在但無人維護） |
| **秘書公司（已認領／付費）** | 通過認領驗證 | 補完 profile、回覆評價、報價、買額度、看分析 |
| **平台審核員** | 內部 | 審核認領、審核評價、處理爭議、審核 AI 建議 |
| **管理員** | 內部 | 數據同步監控、計費、內容管理 |

## 3. 功能需求

### 3.1 TCSP 名單（P0）
- 每日自動從 data.gov.hk / tcsp.cr.gov.hk 抓 `licensees.csv` / `.xlsx`。
- 只顯示 **現有有效持牌人**；被撤銷／過期的標記 `inactive` 並保留歷史（不刪）。
- 每筆顯示：牌照編號、中英文名稱、營業地址、牌照狀態、`last_synced_at`、官方連結。
- 每頁底部：「資料來源：香港公司註冊處 / data.gov.hk。牌照狀態以官方最新公佈為準。本平台非官方機構。」
- 搜尋：名稱（中英、模糊）、牌照號、地區（由地址解析）、服務標籤。

### 3.2 秘書公司 Profile（P0）
- 自動生成頁（官方欄位）+ 認領後補完欄位：
  - 服務套餐與價格區間（註冊／年度秘書／註冊地址／會計報稅／審計／開戶協助）
  - 是否協助開戶、合作銀行類型（傳統銀行／虛擬銀行／EMI）
  - 支援語言（普通話／粵語／英語）、是否支援簡體、是否可遠端辦理
  - 非本地股東經驗、行業專長、成立年份、團隊人數、實體辦公室照片
- **認證等級**：`unclaimed` → `claimed` → `verified`（提交註冊文件+網站+實地地址證明，人手審核）→ `premium`（年費，置頂 + 標章）。三層各自能改什麼、能報幾次價，見 §3.7。

### 3.3 評價系統（P0）
- 任何註冊買家可留評（5 個子分：價格透明度、回應速度、開戶協助、專業度、售後服務）。
- **NNC1 核驗**：買家上傳 NNC1（法團成立表格）→ AI 抽取「公司秘書」欄位 → 與被評公司比對 → 命中則標記 **已驗證評價**（帶徽章，權重更高）。
- 未驗證評價仍顯示，但標示「未驗證」且**不計入**主分數（只計入次要顯示）。
- 秘書公司可**公開回覆**一次。
- 爭議流程：公司可申訴 → 審核員 + AI 仲裁草稿 → 決定保留／隱藏／要求修改。
- 評分演算法見 `RATING_SYSTEM.md`。

### 3.4 RFQ 撮合（P1）
- 買家填需求（公司類型、股東國籍、業務性質、需要哪些服務、預算、時間、是否要開戶）。
- **RFQ Intake Agent** 把自然語言／表單轉成結構化需求。
- 需求公開列在「需求牆」，秘書公司可報價。
- **每家公司每日免費報價 3 個**；超額須購買額度包（見 billing）。
- 報價須填標準化欄位（首年總價、續年價、逐項拆分、是否含政府費用、交付時間）→ 平台自動生成**同口徑比較表**。
- **Quote Analysis Agent** 標記「疑似隱藏費用」「低於市場異常價」。

### 3.5 比較工具（P1）
- 並排比較 2–3 間；欄位：價格、評分、認證等級、服務覆蓋、語言、開戶協助。

### 3.6 教育內容（P1）
- 開公司流程、開戶被拒常見原因、TCSP 牌照為何重要、如何自行核實牌照、隱藏費用清單。
- **Advisor Agent**（RAG）回答問題，僅引用平台自有內容，附免責。

### 3.7 商業化與三層方案（P2）

平台只向 **秘書公司** 收費（COMPLIANCE §6）。三層對應 `providers.Tier` 既有的
`free` / `verified` / `premium`，不新增第四種身分。

| | 通用模式 `free` | 基本付款 `verified` | 進階 `premium` |
|---|---|---|---|
| 取得方式 | 註冊 + 認領頁面（免費） | 年費訂閱（核驗本身對所有層開放，付費買的是優先排審與標記展示） | 年費訂閱（較高階） |
| 可編輯欄位 | 聯絡資料、公司網站、業務範疇勾選 | 全部 profile 欄位 | 全部 profile 欄位 |
| 公司標志（logo） | 可上傳 | 可上傳 | 可上傳 |
| 修改次數 | **一次**；下次可改要滿一年（見下方「更正 vs 更新」） | 不限次數 | 不限次數 |
| 自我介紹 | 無 | 進階自我介紹（長文 + 服務說明 + 團隊／辦公室） | 同 `verified` |
| 報價額度 | 3 次／月 | 15 次／月 | 40 次／月 |
| 名單排序 | 自然排序 | 自然排序 | 置頂展示位（獨立區塊、標示「推廣」） |

**Logo 對所有層開放**：它不是曝光位，是買家在目錄列表裡認出一家公司的方式。
把它關在付費層後面，等於讓免費層的頁面看起來像半成品，而那不是我們賣的東西
（賣的是展示位置，不是辨識度）。上傳一律進私有儲存並掃毒，掃乾淨之後由人閱讀過才複製到
公開儲存——圖片是 `check_banned_phrases()` 讀不到的文字，「保证开户成功」畫在 PNG 裡就繞過了
所有文字檢查，而這張圖會送到每一位訪客眼前。這條路徑**沒有掃毒 override**（認領證明有，
因為那是一位審核員打開一次；logo 不是）。

**完成度分母按層計算**：`profile_completeness` 是排序權重的一部分（RATING_SYSTEM §5，0.12）。
分母只數「該層可編輯到的欄位」，不是全部欄位——否則免費層的頁面無論怎麼填都到不了滿分，
訂閱本身就成了自然排序的加分項，與 COMPLIANCE §6 直接衝突。付費層買到的是更多欄位可以填，
不是同一份表格裡更高的分數。

**成員與擁有權**：一家公司的頁面由 `ProviderMember` 決定誰能編輯，分 owner／staff 兩級——
staff 編輯頁面、回覆評價、處理報價；owner 另外可以邀請與停用成員。加人只有一條路：
owner 發邀請 → 對方用**收到邀請的信箱**登入並按下接受。平台不提供「直接把某個帳號加進公司」，
因為成員身分等於用一家持牌公司的名義說話，那不該由別人替你決定。移除是停用不是刪除
（修改紀錄要留得住），且**一家公司永遠至少保留一位在職 owner**：轉移擁有權的做法是先把同事設為
owner、再把自己改回 staff，反過來的順序在 service 層就被擋下。

**更正 vs 更新**：一年一次的限制只適用於「更新」（換網站、改業務範疇）。
聯絡電話／電郵打錯屬於「更正」，走 moderator 審核的更正申請，不消耗那一次額度也不用等一年——
一個錯的電話卡住買家一年，傷的是買家，不是公司。這條寫在 service 層，不是靠前端提示。
另外，公司網站是認領核驗 token 放置的地方，改網站必須連帶重跑一次網域核驗。

**額度**：報價權有兩個前提——**頁面已認領**，且**公司仍在官方名單上**。
三層現阶段都以**月**為單位（3／15／40）。開站期需求牆一個月只有幾十張需求，
日制上限沒有任何公司碰得到——**碰不到的上限不是商品**。等牆上一天有 20 張以上
需求，再把付費層換成日制（設定寫成 `"15/month"` 這種字串，換鐘只是改環境變數，不用發版）。
免費層 3 次／月是「能證明這個渠道有用，但不夠做業務」。
層級一律看 `provider.effective_tier`，所以置頂被停的頁面（牌照離開名單）同時掉回免費額度。
超出額度後可購買額度包（`billing.CreditPack`），購買的結餘不分週期、跨月結轉，
訂閱額度不結轉。實作：`apps/rfq/allowances.py`（規則）、`QuotaLedger`（流水帳，仍為每日一列）。

**每張需求最多 8 家報價**（`RFQ_MAX_QUOTES_PER_REQUEST`）。稀缺要放在**買家那一側**：
一張需求收到 30 份報價，買家不會覺得選擇多，只會關掉頁面，而那 30 家有 29 家白花額度，
下次就不報了。名額在**開表單之前**就在需求牆上標明（剩幾個名額／已滿），
已撤回的報價不佔名額。

**付費層真正要賣的不是次數**（P7 待做）：新需求的**通知速度**（付費即時、
免費延遲，規則必須在需求牆上寫明）、認證優先排審、`premium` 的置頂展示位、
報價與回應率分析。通知時序可以賣，自然排序不行（COMPLIANCE §6）。

**認證標記**：核驗流程（NNC1／NAR1 等文件人手核對）**對所有層開放**，付費買的是
優先排審與標記的展示位置，不是結論。標記文案只陳述事實——「已提交公司文件並通過核對，
最後核對日 YYYY-MM-DD」——旁邊掛付費披露，且**絕不使用印章圖形**（`docs/BRAND.md` §5.3）。
理由見 COMPLIANCE §2 與首頁那句「买得到展示位置，买不到分数」：我們賣的是做這件事的
人工成本，不是對方值不值得信任的結論。

**除牌後**：`licence_status` 非有效時，該頁面立即唯讀，公司端所有編輯入口消失；
平台側資料（簡介／服務／價格／logo／置頂位）一律不再顯示，目錄卡與詳情頁退回顯示公司名稱首字；成員邀請也一併停用。官方登記冊欄位、除牌標注、
來源與 `last_synced_at`、既有評價仍然保留——那是 COMPLIANCE §1 的要求，也是
「明鏡高懸」對已經付過錢的買家的交代。

- 報價額度包（超出訂閱額度後購買）。
- 導流佣金（**頁面必須明確披露**）。

> 任何向買家收費的產品都會與 COMPLIANCE §6「平台只向秘書公司收訂閱／額度費」衝突，
> 須先經法律評估。

## 4. 非功能需求

- 名單頁 P95 < 800ms（1 萬筆以內用 Postgres 足夠）。
- 每日同步任務失敗須告警（Sentry + email），且**不得覆蓋成空資料**（見 tcsp-data-sync skill 的 sanity check）。
- 支援簡繁英 i18n。
- 內地可訪問性：避免依賴被牆的第三方（Google Fonts / reCAPTCHA / Google Analytics）→ 用自託管字體、Cloudflare Turnstile 或自建驗證、Plausible 自託管。
- WCAG AA 基本可及性。

## 5. 成功指標

| 階段 | 指標 |
|---|---|
| M1 | 名單完整度 100%、日同步成功率 ≥ 99% |
| M2 | 已驗證評價 ≥ 100 條、月活訪客 ≥ 5,000 |
| M3 | RFQ 月發單 ≥ 200、報價回應率 ≥ 60% |
| M4 | 付費認領公司 ≥ 30、MRR ≥ HKD 50,000 |

## 6. 明確排除（Out of Scope v1）

- 平台自己提供公司註冊／秘書服務（會變成競爭者，且觸及受規管活動）。
- 代收代付客戶款項（涉及 MSO 牌照風險）。
- 保證開戶成功率的任何量化承諾。
- 內地境內伺服器與 ICP 備案。
- **高級比較報告（付費 PDF）**——原列於 §3.7，於 Phase 0 移除。向買家收費會踩到
  COMPLIANCE §6 的收費對象邊界，待法律覆核後再決定是否重新納入。
