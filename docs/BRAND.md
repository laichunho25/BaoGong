# BRAND — 包公 BaoGong

> 名字不是裝飾。這份文件說明「包公」兩個字承諾了什麼，以及那些承諾在程式碼的哪一行兌現。
> 寫任何面向用戶的文案前先看這裡；顏色與元件看 `docs/DESIGN_SYSTEM.md`。

## 1. 名字

| | |
|---|---|
| 中文 | **包公** |
| 英文 | **BaoGong**（不寫 Bao Gong、不寫 BAOGONG） |
| 全稱 | 包公 — 香港持牌秘書公司比較平台 |
| 網域 | **www.baogong.com.hk**（apex 轉址到 www；見 `docs/DEPLOY_RENDER.md` §10） |

名字取兩層意思，兩層都要在站上說得出來：

1. **包拯**——中國文化裡「公正、無私、主持公道」的名字。斷案只看證據，不看誰有背景。
2. **包羅香港「公」司服務**——字面上，這個站把香港開公司要用到的秘書服務都收在一處。

一句話版本（footer 每頁都出現）：

> 包公，取「包羅香港公司服務」之意，也取包拯「公道」之義。

## 2. 「包公」不是官 —— 這條先寫，因為它最容易出事

包拯是官。我們不是。名字借的是那個形象裡「公道」的部分，**不是**權威的部分。
所以文案有三件事永遠不准做（COMPLIANCE §1、§2）：

- 不准暗示平台有官方身分、獲官方認可，或代表登記冊說話；
- 不准把平台寫成「判案的人」——我們不替買家決定選誰，也不裁決誰是好公司；
- 不准出現「包過」「包成功」這類把「包」讀成保證的講法（`apps/core/compliance.py`
  的 `GUARANTEED_BANK_SUCCESS` 會直接擋下）。

正面的說法固定為：**「不替你選，只把證據擺齊。」**

## 3. 三條底線 = 包公的三個樣子

平台原本就有三條底線（CLAUDE.md §1）。名字沒有新增承諾，只是給了它們各自一個記得住的形象：

| 形象 | 底線 | 兌現在哪裡 |
|---|---|---|
| **明鏡高懸** | 透明 | 只收錄公司註冊處公布的持牌名單，每日同步；牌照失效不刪頁，改成標注（`registry` app、`data_source_notice`） |
| **鐵面無私** | 可信 | 評價要有 NNC1／NAR1 文件核驗才算數；付費買得到位置，買不到分數（`reviews` app） |
| **一把尺量到底** | 撮合 | 每份報價拆成同一組項目並排比，沒列的留白不算免費；平台不代收買賣雙方任何費用（`rfq` app） |

寫任何一頁時，先問這頁講的是三者中的哪一個，然後用該行的形象詞開頭。

## 4. 語氣

- **短句，動詞開頭，不形容。**「每日同步」不是「極致同步」。
- **講得出處。** 每個數字後面要能指到一張表或一次同步；講不出來就不要寫。
- **敢說我們不做什麼。**「平台不代收費用」「找不到依據就直說沒有」是品牌資產，不是免責注腳。
- 不用驚嘆號，不用「最」「唯一」「第一」（`ABSOLUTE_RANKING` 會警示）。

## 5. 標誌與中式視覺

### 5.1 標誌

`templates/components/logo.html`：**朱砂紅印章**（圓角方形 + 白色內框）刻一個「包」，
右邊是「包公」二字（宋體）與小字 `BaoGong`。SVG inline，不是圖檔——少一個 request，
而且可以跟著呼叫端縮放。favicon（`static/img/favicon.svg`）是同一枚印章。

印章而不是天秤：**這是一個署名，不是一個裁決工具**。名字刻在自己的東西上、對自己說的話負責，
正好是第 2 節要的那種姿態；天秤反而暗示平台在秤誰高誰低，那件事平台不做。

### 5.2 中式元素：用哪些、怎麼用

| 元素 | 在哪裡 | 檔案 |
|---|---|---|
| 印章（朱砂紅） | 頁首、footer、favicon | `components/logo.html` |
| 宋體（`font-display`） | 全站 h1／h2、`.article-body` 標題 | `tailwind.config.js` |
| 回紋 | 頁首下方、footer 頂部各一條細帶 | `.ornament-meander` |
| 祥雲 | 首頁 hero 底邊、「名字的意思」區塊底邊 | `.ornament-clouds` |
| 月牙 | 只在「名字的意思」的 eyebrow | `icon.html` 的 `crescent` |

用的是**民間文化**的符號（印章、回紋、祥雲、包拯額上的月牙），不是**政府**的符號。
香港政府的視覺語言是紫荊與區徽——那些一個都不准出現，第 2 節的紅線在這裡沒有放寬。

### 5.3 三條硬規則

1. **印章永遠不是徽章。** 不准把印章／紅色戳記放在服務商卡片、認證標記、
   或任何官方登記資料旁邊——那會被讀成「本平台蓋章認證」，正是第 2 節禁止的事。
   印章只出現在平台自己的門面上（頁首、footer、favicon）。
2. **`seal` 不是狀態色。** 紅色在這個介面裡已經有意思了：`danger` 代表出事。
   `seal` 只用於品牌家具（標誌、回紋、月牙點綴），一旦出現在 badge、chip、
   表單錯誤或任何會被當成狀態的地方，讀者就要猜這是哪一種紅。
3. **紋樣是裝飾，不承載資訊。** 回紋與祥雲都是 `aria-hidden`、都沒有文字；
   把圖案全部關掉，頁面說的話要一字不少。官方登記資料的區塊維持它自己的灰色底
   （`official-*`），紋樣不得進去。

## 6. 名字出現在哪裡

| 位置 | 寫法 |
|---|---|
| 頁首標誌 | 印章 + 包公 + `BaoGong`（`components/logo.html`） |
| `<title>` | `{頁面名} — 包公 BaoGong` |
| footer | 包公 + 第 1 節的一句話由來 |
| 郵件寄件人／署名 | 包公 BaoGong |
| 內部管理後台 | **不出現**（`admin_site.py` 刻意去品牌化，見該檔 docstring） |

`.com.hk` 是名字的一部分，不只是位址：平台講的是香港公司註冊，網域自己就先說了
主體在香港。這也是為什麼 `.com.hk` 的註冊資格要求（須為香港註冊公司）不是麻煩，
是背書。
